## 1. 黑色命令窗口

实机捕获的父子进程及命令行为：

```text
Photoshop.exe
  -> cmd.exe /c
     -> cmd.exe /d /s /c
        -> python.exe .../sam31_backend/legacy_bridge.py
           -> 已启动/复用的 SAM 本地服务
```

`legacy/SAM31 Image Processor Bridge.jsx` 每张图都执行 `app.system(command)`，其中 command 又显式包装 `cmd.exe`。实际宿主添加了外层 `cmd /c`。这与用户截图的 cmd 黑窗口对应，不是 SAM 的正常进度面板，也不是置信度提示。

`legacy_bridge.py` 启动模型服务时已有 `CREATE_NO_WINDOW`；UXP 原生 supervisor 也已有该标志。只修改最里面的模型进程无法消除前面的 shell。正常复用模型时仍要启动每张图的桥接客户端，所以仍可能每张弹窗。

### 优先级 P0：替换 shell 启动链

建议提供一个不创建 UI 的 Windows 子系统桥接启动器/客户端，避免经 `app.system` 启动命令解释器；直接用无控制台方式启动所需 Python 服务或桥接进程。不能只在原命令上加 `start /min`、换成 `pythonw`，也不能仍通过 `app.system` 启动新启动器。

Windows 的 `CREATE_NO_WINDOW` 可以让控制台子进程不创建控制台；`/SUBSYSTEM:WINDOWS` 的程序本身不要求控制台。这是方案的技术依据，不代表本轮已完成整条启动链改造。[Microsoft 进程创建标志](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags)、[Windows 子系统选项](https://learn.microsoft.com/en-us/cpp/build/reference/subsystem-specify-subsystem?view=msvc-170)。

实施要求：

1. 明确的请求文件交接、请求 ID 校验、结果原子写入和等待完成语义，不能启动后立刻让后续动作执行。
2. 只允许固定运行时与结构化推理请求，不接受任意 shell 命令。
3. 保持按需启动、空闲退出、一次自动重试、技术错误报错、NO_OBJECT 全画布后备。
4. 保留旧脚本事件 ID 与动作参数兼容，现有动作原则上无需重录。
5. 不为了减少闪烁而改回图像处理器同步调用普通 UXP 动作；旧调度器阻塞问题仍需规避。
6. 新客户端须随后端安装器正式部署，版本升级后回归，不能只依赖开发机存在某个工具。

## 2. 画布闪烁

对真实批处理进行窗口标题采样，实际观察到以下阶段：

```text
原照片
  -> FR-SAM-export 临时文档
  -> 原照片：mask / FR SAM temporary mask 临时图层
  -> 原照片：复制图层、调整层
  -> Adobe Photoshop 2026 空文档窗口
  -> 下一张照片
```

源码解释：

- 输入导出复制整个文档，然后复制活动层、隐藏其他图层、导出 PNG、关闭临时文档。这造成额外文档切换。
- 掩码置入后要校正位置和尺寸，当前在这些操作之后才设置 `visible=false`。函数名虽为“隐藏置入”，但不能据此保证置入过程从未可见。
- 图像处理器自己的逐张打开/关闭，以及用户动作中的“选择并遮住”、调整层操作，也有宿主重绘。不能把所有闪动归于一个原因，也不能承诺整个 Photoshop 工作流零闪烁。

### 优先级 P1：单背景图层安全快路径

在用户文件夹一张 5027×5027、单背景图层、无 ROI 的真实图片上运行 `tests/photoshop/probe-background-export.jsx`：

| 路径 | 单次观测导出耗时 | 是否创建临时文档 |
|---|---:|---|
| 当前安装桥接的 `saveInputPlanes` | 1347 ms | 是 |
| 当前文档直接另存 PNG 副本（asCopy=true） | 578 ms | 否 |

解码后 RGBA 字节逐一相同，ICC 相同。两者 RGBA SHA-256 都是 `039a6fef6c1ec9e20c9d8f343d3c6ac4d192c091c0127aa4b8d6f8387c73f9e1`。文档名称、已保存状态、历史状态、活动层、文档数量检查通过，源照片未保存改动。

这是一个样本的可行性证据，不是通用性能保证。正式加入时应仅在严格的单背景、RGB8、无 ROI 等已验证条件下启用；多图层、智能对象、透明度、样式和非标准活动通道等继续使用可靠路径，不能改变“只读取当前活动图层”的约定。需要更多样本、中文路径及异常恢复测试。

### 优先级 P2：临时掩码的不可见导入

先验证在隐藏容器内置入掩码、再载入其透明度的方案；至少应避免等到全部变换完成后才隐藏。必须比较最终灰度选区、全画布坐标、严格 ROI、原活动层/通道恢复及失败回滚，不能只看画面不闪就验收。

## 推荐执行顺序与验收

1. 首先替换 shell 启动链，目标是正常成功路径不出现命令窗口、不因桥接客户端抢走其他应用焦点。
2. 然后加入单背景输入快路径，减少每张额外文档切换。
3. 最后优化掩码置入可见性，区分桥接闪烁与图像处理器自身打开/关闭的正常切换。
4. 在同一 24 张文件夹、同一动作、同一输出设置下回归；比较输出尺寸、名称、选区语义、无对象继续、技术错误、后台运行和原文件哈希。
